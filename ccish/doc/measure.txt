Measurements of ccish

Written by tools/measure.py (make measure; make test refreshes it).
Other checks (AGENTS.md's "Measuring" says how to use each):
  tools/fsize.py         each function's code and frame (-f, the largest
                         frames first; -c, two listings compared)
  tools/gencmp.sh BASE   does this tree write the same code as BASE?
  tools/opcount.py BASE  the ops the run tests take, against BASE's
  make profile           where the passes spend their time
  tools/opstats.py       the commonest ops and runs of ops
  tools/loops.py         accesses in loops to globals moved to the heap
  doc/limits.md          each limit, with its measured peak

Contents, in order (each part starts with the text quoted):
  "The small build:", each source file's code, data, strings and zero
    data; "The library:", the same for each library object
  "ccpp's tables:" (and cccomp's, ccgen's): the most one source needs
  "ccpp:" (and "cccomp:", "ccgen:", "cclink:"): each program's totals,
    its stack at worst ("the worst frame chain") and its fit on an Apple II
  "Peaks:", each limit, the most ccish's own source uses, and where
  "Disk space:", each image's parts and size, in bytes and in blocks
  "And their fit on a 64K Apple II": each program's need and spare

File: the whole file's bytes; Total, all of them. An image file's parts, in
its order: a 12-byte header (the same in every image), Names (the
dependencies' and imports'), Table (the function table, 2 bytes a function,
init too), Data, Code and Fixups. Not in the file: (Zero), the zero region,
the disk space saved, shown where it goes in memory, after Data (init
clears it); (REL), the same program as a REL module, for comparison. XLOAD
is a REL module, and XLOAD2, its second part, an image. Blocked: the disk
space the file takes on a ProDOS disk, in whole 512-byte blocks (a disk
can't give a file part of one): its data, rounded up, and for a file over
one block, its index block.
XLOAD in memory: its first part 4451, its second part 3879, placed
(none of it stays once the program runs).

XLOAD: PLASMA's loader reading XLOAD's whole file (RLD and ESD too) and FILEIO
(1998). A program loading: FILEIO, the program (its def table, data, zero
region and code), XLOAD's second part if it's above the program, and 512
for frames, as XLOAD checks; running: FILEIO, the program, the frame stack
and I/O buffers (at their worst, 1280 each).
* A lower bound: unbounded recursion can take more frame stack.
